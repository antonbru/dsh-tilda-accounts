# dsh-tilda-accounts

Клиентские MCP-учётки Tilda в DSH: добавить, удалить и переключить активную без правки YAML и перезапуска.

```
Settings → Tilda            добавить / удалить / заменить ключ / выбрать активную
чип «Tilda · Клиент»        переключение из-под композера
/tilda use acme             переключение из чата
```

Агенту доступен инструмент `tilda_accounts` (`list`, `use`, `status`, `add`, `remove`). Для настоящих клиентских ключей используйте Settings → Tilda: ключ, переданный в `add`, останется в логе сессии. `add`/`remove` удобны для служебных и тестовых подключений.

## Как работает

- Учётки хранятся в `Config` этого плагина: `accounts[]` + `activeId`. Поля помечены `volatile()`, поэтому страница настроек пишет их через штатный `ctx.remote.settings`, а Loader применяет изменение без перезапуска плагина.
- Активная учётка монтируется как экземпляр `@deepseek-ai/dsh-mcp-client` с `serverName: tilda`; при переключении старый экземпляр снимается, новый поднимается. Инструменты всегда называются `mcp__tilda__*` и относятся только к активной учётке.
- В системный промпт добавляется строка об активной учётке и проекте, чтобы агент не путал клиентов.
- Токен помечен `role('secret')`: браузер получает только признак «ключ задан», не значение.

## Ключ Tilda

MCP-адрес **фиксированный** для всех учёток: `https://tilda.ru/api/mcp`. В форме «Добавить учётку» его нет — заполняются только название, проект и ключ.

Ключ создаётся в [Profile → MCP server → New key](https://help.tilda.cc/mcp), с привязкой к проекту. Ключ проектный: на каждый проект нужен свой ключ. Отдельный аккаунт «Tilda Dev» — только удобство администрирования, плагин работает и без него.

Ключ уходит как `Authorization: Bearer <ключ>` — это подтверждает ответ сервера (`WWW-Authenticate: Bearer realm="tilda-mcp"`). В транспорте адрес нормализуется на `https://tilda.ru/api/mcp/`: bare-путь отвечает 301, а редирект превратил бы POST initialize в GET. Публичная константа остаётся `https://tilda.ru/api/mcp`.

## Установка

Репозиторий: <https://github.com/antonbru/dsh-tilda-accounts>. Проверено на DSH `0.2.1-rc.2` (Desktop, macOS).

### Из GitHub

```bash
git clone https://github.com/antonbru/dsh-tilda-accounts.git
cd dsh-tilda-accounts
pnpm install
```

Затем в сессии DSH:

```
plugin_manager install_bundle <полный-путь-к-папке-плагина>
```

Можно установить сразу git-адресом — pnpm подтянет зависимость сам:

```
plugin_manager install_bundle https://github.com/antonbru/dsh-tilda-accounts
```

Для приватного репозитория коллегам нужен доступ к GitHub (SSH-ключ или token в pnpm). Публичный репозиторий проще: ссылки достаточно.

Если папка уже склонирована, выполните в ней `pnpm install` и передайте в `install_bundle` полный путь к этой папке.

После установки откройте Settings → Tilda и добавьте первую учётку. Если инструменты не появились, проверьте в чате `/tilda status` — там будет ошибка подключения.

## Ограничения

- Активна одна учётка одновременно; переключение глобальное и действует на все сессии.
- Токены лежат в профильном `cordis.patch.yml` (файл 0600), как у остальных MCP-подключений профиля. В браузер они не попадают. Перенос в `credentials` — возможное развитие.
- Долгий вызов Tilda во время переключения может завершиться ошибкой: его инструмент снимается вместе с учёткой.

## Удаление

```bash
plugin_manager remove_bundle dsh-tilda-accounts
```
